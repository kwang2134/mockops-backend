# 백엔드 주요 기술 스택 및 핵심 라이브러리

## 🛠️ 백엔드 기술 스택 및 라이브러리 선정 초안

### 1. 🚀 핵심 프레임워크 및 언어

| **구분** | **선택 스택** | **선택 이유** |
| --- | --- | --- |
| **주요 언어** | **Java (JDK 21+)** | 안정성, 엔터프라이즈 환경에서의 높은 점유율, 풍부한 개발 생태계 및 도구 지원. |
| **프레임워크** | **Spring Boot 3.x** | 빠른 개발 시작, 자동 구성(Auto-Configuration), Spring Data JPA 등 광범위한 생태계 통합. |
| **빌드 도구** | **Gradle** | Kotlin DSL 지원 및 유연한 의존성 관리. |

---

## 2. 💾 데이터베이스 및 ORM

| **구분** | **선택 스택** | **선택 이유** |
| --- | --- | --- |
| **주요 관계형 DB** | **PostgreSQL** | 뛰어난 성능과 안정성, JSONB(JSON Binary)를 포함한 풍부한 데이터 타입 지원, 복잡한 쿼리 처리 능력. |
| **ORM** | **Spring Data JPA** | Java 객체와 DB 매핑 표준, 레포지토리 패턴을 통한 간결한 데이터 접근 구현. |
| **DB 마이그레이션** | **Flyway** 또는 **Liquibase** | DB 스키마 변경 이력을 관리하고 배포 시 자동 적용하여 버전 관리를 보장. |

---

## 3. 🛡️ 보안, 인증 및 인가

| **구분** | **선택 스택** | **선택 이유** |
| --- | --- | --- |
| **핵심 보안** | **Spring Security** | 인증/인가의 표준 프레임워크. JWT 필터 및 OAuth2 처리, 메서드 레벨 보안(`@PreAuthorize`) 적용에 필수. |
| **JWT 처리** | **jjwt (Java JWT)** | JWT 생성 및 검증을 위한 라이브러리. WebHook 토큰 및 Access Token 관리에 사용. |
| **암호화** | **Java JCA (AES-256 GCM)** | WebHook Secret Key의 양방향 암호화 및 복호화를 위해 표준 Java 암호화 기능을 직접 활용. |

---

## 4. 🔗 비동기 처리 및 운영

| **구분** | **선택 스택** | **선택 이유** |
| --- | --- | --- |
| **인메모리 Cache** | **Redis** | **헬스 체크 스케줄링 목록 관리**, Refresh Token 저장 및 세션 관리에 사용. 빠른 읽기/쓰기 성능 확보. |
| **스케줄링** | **Spring `@Scheduled`** | 정해진 주기(5분, 10분, 30분 등)에 따른 **벌크 헬스 체크** 작업 실행. |
| **로깅** | **Logback (SLF4J)** | Spring Boot 기본 로깅 표준. 구조화된 로그 출력 및 레벨 관리에 용이. |
| **API 문서화** | **SpringDoc OpenAPI** | YAML/JSON 기반의 Swagger 문서를 자동 생성하여 프론트엔드 연동 명세의 보조 자료로 활용. |

### 🔍 요약: 핵심 라이브러리 선택

| **영역** | **라이브러리** | **용도** |
| --- | --- | --- |
| **DB 관리** | **Spring Data JPA** | 엔티티와 레포지토리 정의 |
| **인증/인가** | **Spring Security & jjwt** | OAuth2, JWT 필터 및 토큰 발급/검증 |
| **분산 환경** | **Spring Data Redis** | 헬스 체크 스케줄러 목록 및 캐시 관리 |
| **운영** | **Flyway** | DB 스키마 버전 관리 |
